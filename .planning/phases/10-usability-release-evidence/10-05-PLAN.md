# 10-05 — Formatting that refuses rather than guesses

Closes T10-04 and T10-05.

```js
catch (_err) { return new Date(value).toLocaleString(); }
```

On any error this formats in the **browser's** locale while the rest of the
screen uses the configured one. Two date formats on one control-room screen is
an ambiguity defect: `03/09` and `09/03` are the same instant written two ways
and nothing says which is which.

**A formatter that cannot format refuses.** It returns the marked-unreadable
sentinel Phase 7 already established for a point it cannot read — the pattern
exists, and a second invented behaviour for the same situation is the drift this
codebase keeps closing.

**Plurals become data.** `gaps === 1 ? "Lücke" : "Lücken"` is correct for two
languages and a code edit for every other. A category table keyed by the CLDR
plural categories expresses more than two forms without code.

Both runtimes are compared as **canonical bytes**. Four byte-parity traps so
far; a values-equal comparison would have passed each of them.

## Steps

1. `locale-format.mjs` / `locale_format.py`: date, time, number, unit, plural.
2. Remove the `toLocaleString()` fallback and the hardcoded `"de-DE"` default.
3. A shared corpus across locales, timezones and DST boundaries, committed
   before either implementation reads it.

## Acceptance

Restoring the fallback fails. A three-form plural locale is expressible in the
table with no code change, proven by a fixture locale in the test.
