# 10-09 — The automated sweep, and what it is not

Closes T10-09 and T10-15. Grep group `phase-10-axe`.

`axe-core`, pinned exactly. It runs in-page, needs no service, and its rule
metadata names the WCAG criterion each violation maps to — which is what a
registry entry has to cite.

**A surface not swept fails.** The same drift guard the exact-dist runner
learned in Phase 9: a hardcoded list of surfaces silently skips new ones, and a
suite that reports success for tests it never ran is worse than no suite. The
spec enumerates registered custom elements and fails if any is unswept.

**No rule is disabled to get green.** A disabled rule is a claim with no
evidence, which is this phase's whole subject. If a rule cannot pass, the finding
is fixed or the claim is published as failed.

**This sweep is not a conformance claim**, and 10-11 is where that is enforced
rather than merely written down here.

## Steps

1. Pin `axe-core` in `devDependencies`; confirm `verify:release` accounts for it.
2. `product-axe.spec.mjs`: mount every registered element, run the sweep, fail
   with the violation list including each rule's WCAG mapping.
3. The unswept-surface guard, mutation-verified by adding an element and
   watching the guard fire.

## Acceptance

Zero violations, no disabled rules, and an unregistered new element fails the
coverage guard. The dependency is pinned to an exact version, never a range.
