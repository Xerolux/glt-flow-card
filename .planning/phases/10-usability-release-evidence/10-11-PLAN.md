# 10-11 — The registry, and the two claims it refuses to merge

Closes T10-10, T10-11 and T10-12. **This is the phase.**

A claim carries the command that supports it and the result of running it:

```
claim:     the shipped surfaces expose accessible names
evidence:  npm run test:a11y
result:    pass, 2026-09-02, 41 surfaces swept
covers:    WCAG 2.2 4.1.2 (partial — automated subset only)
```

Three properties, each closing a row:

**A claim with no evidence fails the build** (T10-11). Not a warning. A claim
nobody can support is what this phase exists to stop shipping, and the failure
mode is already present: `README.md` says "`test/` – lightweight validation
tests" while the suite is 476 Node, 691 Python and 81 browser tests. Harmless
today, harmful the day a claim goes stale in the other direction.

**A failed claim is published as failed** (T10-12). Omitting it lets its absence
read as "not applicable" — the counting-oracle shape from Phase 9, one level up.

**Automated and manual accessibility evidence stay separate** (T10-10). Automated
rules decide a minority of WCAG criteria by construction; "automated checks pass"
merged with "manual pass recorded" into "WCAG 2.2 AA" is a conformance statement
neither piece of evidence supports. The registry has no schema in which the two
can produce a conformance claim, so the merge is not a policy someone can
override — it is a structure that has no field for it.

**T10-10 and T10-13 are this phase auditing itself.** Both describe a claim this
phase is in a position to make and would be believed about. That is why the
registry is a build step: a document is edited by whoever wants the claim.

## Steps

1. `claims.json`: claim, evidence command, coverage, and what it explicitly does
   not cover.
2. `claim-registry.mjs`: run each evidence command, record the result, refuse a
   claim with none, publish failures as failures.
3. `claim-registry.test.mjs`: the three mutation cases — evidence removed,
   evidence failing, merge attempted.

## Acceptance

Each mutation fails with a message naming which rule it broke. The registry's
output names every claim, including the failed ones.
