# 10-02 — One catalog, and completeness as a computation

Closes T10-01.

Today wording lives in at least fourteen modules across two runtimes, which is
why "complete German and English catalogs" cannot be *checked*: nothing
enumerates what complete means.

**Two catalogs, one lookup, and the lookup refuses.** The `src/v100/` surfaces
already throw at module load when a key lacks a language; this generalizes that
one check to one place, so it stops being nine copies that can each be forgotten.

The lookup **does not fall back to English.** That is the whole point of
10-03 and it starts here: a missing German string is a defect, not a rendering
strategy.

## Steps

1. `catalog-de.mjs` and `catalog-en.mjs` as flat, sorted key/value maps.
2. `catalog-lookup.mjs`: `text(key, language, ...args)` which throws on an
   unknown key and on a key missing the requested language. No `?? en`.
3. Move the existing per-module `TEXT`/`COPY` tables into the catalogs, module
   by module, keeping the keys namespaced by surface (`sites.unreachable`).
4. `test/catalog-completeness.test.mjs`: both catalogs have identical key sets;
   neither is empty; every key is reachable from a module.

## Acceptance

Removing one German wording fails the test **by name**. An empty catalog fails
rather than trivially passing. Mutation-verified in both directions.
