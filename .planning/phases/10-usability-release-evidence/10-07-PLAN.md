# 10-07 — Names and roles, on elements rather than on attributes

Groundwork for T10-07 and T10-08; the assertions land in 10-08.

The shipped runtime has **zero** `aria-label` attributes against five
`placeholder=` and three `title=`. A `title` is not an accessible name for a
control and a `placeholder` disappears the moment someone types.

The Phase-8 and Phase-9 surfaces have **no roles at all** — `span` and `ul` with
`data-*` attributes. That is this work's own gap, and it is listed here rather
than quietly fixed, because the tests those phases wrote checked colour
independence and text content and I took that for sufficient.

**Use the element, not the attribute.** `<button>` before
`<span role="button">`; a real `<ul>` before `role="list"`. An element that is
what it claims to be is focusable, operable and announced without further work,
and it stays that way when someone edits the markup later.

**The name says what it does.** "Alarm quittieren", not "Schaltfläche". It comes
from the catalog, so it survives translation.

## Steps

1. The legacy base: replace `title`/`placeholder`-as-label with real labels and
   real elements. Change markup, not styling.
2. `project-sites.js`: the absent-site list becomes a list with a description
   naming the count; the health badge's state text is the badge's name rather
   than a sibling span.
3. `project-assets.js`: the same treatment.

## Acceptance

No behaviour or wording changes. Assertions are 10-08's; this plan ends with the
markup correct and the suites still green.
