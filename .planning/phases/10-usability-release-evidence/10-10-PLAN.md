# 10-10 — A harness that measures, and says where

Groundwork for T10-13 and T10-14.

The roadmap names the defect this replaces: *a 2,000-object diagnostics
micro-test presented as platform capacity*. The correction is not a bigger
micro-test.

**Scenarios are committed before anything measures them**, at 100, 500 and 2,000
objects, covering render, live updates, routing, editing, persistence and remote
partial failure — the dimensions TEST-01 names, not the ones that are easy.

**Every measurement carries an environment fingerprint**: CPU model and count,
memory, whether a CPU allocation is declared, Node and browser versions, and a
`representative` flag that is **false unless a human sets it for a named host**.
Nothing in the harness can set it true.

**A scenario that builds nothing fails.** The effect line carries the object
count actually built and asserts it against the declared size. A capacity test
that finishes in three milliseconds because it built no objects, reported as a
budget pass, is this phase's vacuous pass — and it is the most believable one,
because it looks like good news.

## Steps

1. `capacity-scenarios.json`: sizes, dimensions, and what each measures.
2. `capacity-harness.mjs`: run a scenario, emit measurement plus fingerprint.
3. The build-count assertion and its mutation test.

## Acceptance

A scenario declaring 2,000 and building 0 fails, naming both numbers. The
fingerprint is present on every measurement and `representative` is false here.
