# 08-13 — Bounds on evidence and storage

**Status:** complete. Closes T8-20.

D24 is unusual among this phase's defects: the feature did not exist, so there
was nothing to fix. That is exactly why the bounds came first — adding
attachments without limits would have **created** the leak rather than inherited
one.

**Limits are readable before a file is chosen.** A limit discovered by hitting it
is a limit that wasted the work, and in a plant room that work is a photograph
somebody climbed a ladder to take.

**Refused, not truncated.** A half-stored photograph looks like evidence and is
not — Phase 6's silently-capped shelve in a new subject.

**The type is checked by content**, because a filename is a claim made by whoever
typed it. This is not virus scanning and the documentation says so; it stops the
obvious mislabelling that would let a surface render arbitrary bytes as an image.

**An open work order is never pruned**, however old: age is not a reason to
forget about work that has not been done. An unreadable timestamp keeps the
record, because throwing away evidence over a formatting problem is the wrong
trade. Pruning is recorded, since a record that vanished without explanation is
worse than one that was never kept.
