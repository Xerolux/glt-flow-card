# Phase 05 Threat Register

Every Phase-5 threat is a release blocker until its owner command passes against
behavioral tests and, where applicable, the exact generated artifacts. Phase 5
adds no authority; it adds *content and geometry*, and an extension format that
must add content without adding execution. Its threats are therefore about
claims that outrun evidence, geometry that is unstable under small changes, edits
that cannot be undone, and a contribution that becomes code. No test may contact
a live Home Assistant, remote site, fieldbus or plant target.

## ASVS L1 Mapping

| ASVS area | Phase-5 control |
|---|---|
| V1 Architecture | A contribution is data interpreted by first-party code; no contributed script is loaded or evaluated in any realm. |
| V5 Validation | Extension manifests, symbol geometry and imported projects are validated against a closed schema with bounded size, depth and count before use. |
| V12 Files | Symbol packs and masters travel through the existing ZIP32 trust boundary; no new extraction path is created. |
| V14 Configuration | Namespaces, versions and conflicts are resolved deterministically, and an unresolvable conflict fails installation rather than picking a winner. |

## Blocking Rule

Phase closure may change a row to `verified` only when the listed owner command
passes, emits non-skipped behavioral evidence, and the Phase-5 evidence manifest
binds the command output to the exact generated artifacts. Any HIGH finding,
missing owner, skipped test, zero-test run, unbounded path, live target,
evaluated contribution or non-zero unintended service effect blocks release.

T5-16 has one canonical non-recursive owner: `npm run test:phase5:release`. The
outer `npm run test:phase5` / `tools/verify-phase5.mjs` chain may invoke that leaf
exactly once, and nothing reachable from it may call back into either.
