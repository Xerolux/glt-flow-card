## Phase Goal

**As a** site owner, **I want** one card to be unable to ask for everything, **so that** a dashboard cannot take the Recorder down.

<objective>Bound every query dimension and refuse past the bound.</objective>

<tasks>
<task type="auto">
  <name>Task 1: The three bounds</name>
  <files>custom_components/glt_flow_card/history_bounds.py, custom_components/glt_flow_card/const.py</files>
  <action>Fix D3 and T7-02. Nothing in the Recorder API bounds a raw query — not rows, not entities, not window — so the bound is ours. Enforce a maximum window, a maximum entity count and a maximum row count, each a configured number with a conservative default. Follow Phase 6's treatment of the alarm philosophy exactly: build the mechanism, configure the policy, default conservatively, and document each default as a site decision rather than a product opinion.</action>
  <acceptance_criteria>
    - Each bound is configurable and each shipped default is the conservative value.
    - The bounds are enforced before the query runs, not after the response returns.
    - The response declares whether it reached the row cap.
  </acceptance_criteria>
  <verify><automated>py -3.13 -m pytest tests/components/glt_flow_card/test_history_bounds.py -q -x</automated></verify>
  <done>Every dimension is bounded.</done>
</task>

<task type="auto">
  <name>Task 2: Refuse or downgrade, never truncate</name>
  <files>custom_components/glt_flow_card/history_routes.py</files>
  <action>A window past the raw limit is either refused with the limit named or answered from statistics and **labelled** as such in the result's `source`. It is never silently truncated: a truncated window produces a chart of the wrong period that looks exactly like a chart of the right one, which is this phase's defining failure mode. Phase 5's rule governs — refuse, do not degrade — and Phase 6's addition applies: the refusal carries a reason, because a bare refusal tells an engineer the tool disagrees with them while a reason tells them which of the two is wrong.</action>
  <acceptance_criteria>
    - A over-long window is refused with the limit in the message, or downgraded with `source: "statistics"`.
    - No path truncates a window silently.
    - Every refusal reason is a member of a closed set.
  </acceptance_criteria>
  <verify><automated>py -3.13 -m pytest tests/components/glt_flow_card/test_history_bounds.py -q -x</automated></verify>
  <done>T7-02 passes.</done>
</task>
