# Plan 02-05 Summary — Browser Reducer and Exact-Dist RED Contracts

## What was built

**Task 1 — authority and collaboration reducers.**
`test/phase2-authority.test.mjs` names the ten events that must produce a
read-only shared mode *in the same reducer transition* — absent, loading, stale,
rejected, incompatible and sequence-gapped authority, a revoked role, an expired
or lost lease, and a Companion disconnect — and fixes the lease renewal
thresholds at 40% of TTL for a dirty candidate and 50% for a manual prompt on an
idle clean lease. The sentinel drives the reducer through the whole sequence:
the initial state is not writable, a capability snapshot alone is not writable,
a snapshot plus a held engineering lease is, and every loss event returns it to
read-only with a reason and without a bearer token in the state.
`test/phase2-collaboration.test.mjs` fixes the seven events after which a dirty
candidate must survive and the only two that may clear it, excludes overwrite
and force from the conflict choices, and requires `configured-control.mjs` to
expose no `scheduleRetry`, `autoRetry` or `redispatch` at all.
Both modules are imported dynamically so a missing module is reported as a named
product gap rather than crashing the run as a broken harness.

**Task 2 — shared authoritative two-browser fixture.**
`test/e2e/fixtures/shared-authority.mjs` is one Node coordinator that owns the
roles, content and access revisions, the single exclusive lease with its
bindings and expiry, the event sequence, opaque evidence cursors, control
results and injectable faults. Two isolated Playwright contexts talk to it over
a per-page exposed binding, so each has its own session identity and storage
while sharing one authority. Nine fixture tests prove the coordinator itself is
trustworthy before any product assertion rests on it: the role matrix matches
the Python contract, hidden and missing projects answer identically, exactly one
lease is granted and the denial never names the holder, expiry has no grace
period, a second write produces a real revision conflict, a caller-authored
target is refused with zero service calls, a control resolves its whole effect
from its definition, a restart invalidates every lease and cursor, and remote
routes stay `feature_unavailable`.

**Task 3 — exact-dist Phase-2 UI scenarios.**
`test/e2e/project-authority.spec.mjs` adds the `phase-2-fixture-seed` and
`phase-2-ui` grep groups. Both mount the committed generated bytes in two
contexts, assert the effect ledger and the seeded-secret scan are clean, and
then make one product-completeness assertion each.

**Phase-2 gate.** `tools/phase2-red-gate.mjs` runs all twelve registered RED
commands through the classifier and passes only when each one reaches exactly
its named sentinel with nothing else broken. `test:phase2` and
`test:phase2:quick` now point at it. Plan 02-17 replaces it with
`tools/verify-phase2.mjs`; this tool never invokes either Phase-2 entry point.

## Decisions

- `playwright.config.mjs` honours an optional `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.
  A container may ship a Chromium build whose revision does not match the pinned
  Playwright version; without this the browser cannot launch at all, and the
  classifier correctly rejects that as a harness failure rather than a RED. The
  pinned Playwright version and CI's own browser resolution are unchanged.
- The exact-dist runner now runs both spec files. The grep groups keep each
  controlled RED command scoped to exactly one sentinel.
- The reducer tests import their modules dynamically. A static import of a
  missing module raises `ERR_MODULE_NOT_FOUND`, which the classifier rejects as
  a harness failure — correctly, but it would make the RED unusable.
