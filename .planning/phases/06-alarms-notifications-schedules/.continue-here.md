## Carry these forward

- **Commit source → `npm run build` → `npm run stage:hacs` → commit manifest →
  re-run gates.** Phase 5 lost several cycles to this ordering, and Phase 6 lost
  three more (06-01, 06-02, 06-15) — each time CI reported "staged build
  manifest identity disagreement" on the source commit.

  **Push only after the manifest commit.** The intermediate commit is
  *inherently* stale and cannot be amended away: `build.commit` records the SHA
  of the last commit touching a canonical source, so building before committing
  records the previous SHA, and amending afterwards changes the SHA the manifest
  just recorded. The two-commit sequence is required; what is optional is
  whether the world sees the first one on its own. Batch the push.
- **A claim about the card is checked against `dist/glt-flow-card.js`.** Phase 5
  found retirements that existed only in files nobody ships.
- **A route must be declared in both `policy.py` and `policy_contract.py`,** and
  every request field must be `vol.Optional(..., default=...)` or the prober
  returns `invalid_format`.
- **No live Home Assistant writes, no real notification recipient, no release.**
  `release_authorized` stays false.

## Known environment limits

- `npm run test:phase6:release` needs a Docker engine this container does not
  have, so T6-21 is expected to stay `planned` — exactly as T5-16, T4-14, T3-14
  and T2-16 did.
- `api.github.com` returns 403 through the egress proxy, which is the
  source-repository half of `verify:provenance --online`.
- **A deliberately-failing test must never reach the HA lane.** The lane writes
  its own `pytest.ini` inside the container and refuses any deselected test, so
  `tools/test-ha-artifacts.mjs` removes files carrying `expected_red` or
  `escaping_notification` from its workspace copy. Match on the *marker*, never
  on `test_expected_red_*` — that name matches every phase's sentinel, 28 files,
  most long since green and carrying the lane's real coverage.
- **Playwright.** This container has Chromium **1194** while the pinned
  Playwright **1.62.1** looks for **1234**, so every exact-dist run needs
  `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`.
  `playwright.config.mjs` already supports the variable. The mismatch is
  pre-existing — `--grep=phase-5-catalog` fails the same way without it and
  passes with it — so do not read the failure as a Phase-6 defect.
